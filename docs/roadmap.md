# bambiui implementation status

## Product decisions

The English-only Studio uses fixed neutral editor palettes following the selected Light/Dark mode. Header, sidebar, inspector and the outer canvas share #FAFAFA in Light and #202020 in Dark; canvas tools, Develop and portaled dialogs use the same surface family. Editor colors are independent of the user's background and primary colors. Thin borders, spacing and selected states distinguish regions rather than differently tinted panels. The header mark keeps its brand color and semantic status indicators retain their colors. Design-system tokens and export values are unchanged. Design displays one preview at a time. Use the icon-only Light/Dark switch at the top right of the Design canvas to target manual color editing; Develop keeps the switch in its header to inspect either theme's reference. Non-color edits update both themes, including the shared `fontFamily` preset and `spacingSm`/`spacingMd`/`spacingLg`. There is no editor appearance switch, Compare mode or Scenario context; Develop focuses on code and token references.

The Color builder accepts one brand color. A valid six-digit hex value or preset immediately generates and applies both light and dark global color roles in a single update. Invalid/incomplete input does not change the saved system. Shared numeric values, typography, component overrides and name remain untouched. Existing imported systems with different light/dark sources retain them until a new color is chosen; manual color edits still target the selected theme only.

The studio stores its schema-v3 system locally; v1/v2 migration copies historical values to both themes without recoloring and supplies new preset defaults. Older v3 records without presets receive `system` and 4/8/16px while preserving legacy padding/gap and color values. Curated Google Fonts preset IDs fit the existing schema v3: JSON backups store the chosen ID in both theme records, not remote stylesheets or font files, and Light/Dark continue to share all non-color tokens. Both-theme CSS exports include `--ds-font-family`, `--ds-spacing-sm/md/lg`, raw scale stops, derived colors and system constants; a selected Google preset adds a stylesheet `@import` at the top, before both theme selectors, while `--ds-font-family` holds the resolved stack with local fallbacks. Local presets add no import. Auth, server persistence and account-based saving remain outside scope. The separate palette CLI still emits raw scales and roles when detailed recipes are needed.

## Implemented capabilities

- The project name is editable in the sidebar on desktop and mobile; Design/Develop links sit beside the logo, with icon-only theme switching and canvas-top Undo/Redo controls in Design. Seven components (Button, Input, Switch, Checkbox, Card, Badge, Text) with consistent APIs and interactive Design specimens on a pan/zoom canvas with the selected theme's dotted background. Fit and zoom controls are available on desktop and retain the Studio font independently of the specimen. At 760px and below, the preview and inspector use natural page scrolling; narrow desktop canvases separate the help and zoom controls to avoid overlap. Actual Card specimens retain their own tokens. Mounted previews retain demo state when switching views or themes.
- Design-only inspector for 30 global tokens and optional per-component overrides; colors are theme-specific, while numeric and typography tokens are shared. Override controls describe variant/state limitations when the component CSS remaps a token. The contrast summary appears outside Shape & spacing, highlighting failed checks; details list modeled color pairs and warnings, including manual color failures. On narrow screens, jump links connect the workspace and inspector without adding tabs.
- OKLCH generation of accessible light/dark usage colors from one source, preserving the source in JSON. A safe light brand source can remain the exact primary fill with dark ink; links use derived accessible text ink. The fresh system's primary and the header mark both retain the brand source; editor controls stay neutral. Generated defaults pass 133 modeled color pairs per theme; manual or legacy values may not.
- Develop view with React examples, props/defaults, live aliases, raw color scales, derived values and full CSS, without a token inspector. Copyable snippets are type-checked against real component APIs; they are project examples, not a standalone component package.
- Shared `fontFamily` presets (seven local choices: `system`, `sans`, `humanist`, `serif`, `editorial`, `mono`, `typewriter`; curated Google Fonts choices alongside them) and spacing presets `spacingSm`/`spacingMd`/`spacingLg` (4/8/16px default). Card.Content consumes the corresponding preset for the gap between children at each Card size. Legacy `paddingX`, `paddingY` and `gap` globals and component aliases remain independent; no implicit remapping.
- Google Fonts are opt-in: selecting a Google preset triggers browser requests to `fonts.googleapis.com` for CSS and `fonts.gstatic.com` for font files, sharing request data such as IP address with Google. Local choices do not request hosted fonts; offline/blocked remote fonts use local fallbacks. Exported CSS with a Google import can make the same requests for consumers unless they remove it or self-host fonts.
- Export of both-theme CSS (including the resolved font stack, spacing presets and raw color scales) and JSON backup/import, with v1/v2 migration and v3 round-trip. Import resets the generator input to the imported source; token input drafts remount with the imported system.

## Validation and outstanding acceptance

- Run `npm run build`, `npm run lint`, `node --experimental-strip-types --test app/studio/*.test.mjs`, `node scripts/check-checkbox-server.mjs` and, after the main build, `node scripts/studio-smoke.mjs`. The isolated Checkbox fixture checks server prerender and client references, not browser hydration.
- Smoke tests exercise the single visible theme preview, one-step generation and invalid input, selected-theme color overrides, contrast warnings, view/theme retention, export/import, accessible names, readonly choices, required email, a controlled form with native `FormData`, an action-handler-backed loading state and responsive reflow. Optional `--screenshots` writes review images; there is no pixel regression suite. The old localization/appearance/structural-baseline tests are obsolete and have been replaced with checks of the current workflow.
- **Full accessibility acceptance remains open:** Chromium AX inspection and responsive reflow cannot replace VoiceOver and browser-native 200% zoom. Complete the manual checks in `docs/accessibility-checklist.md` before claiming full WCAG conformance.
